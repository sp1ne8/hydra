# HYDRA — версия для доработки frontend

Это самостоятельный HTML/CSS/JS-сайт. Все тексты и карточки уже находятся в HTML и видны без JavaScript. Для просмотра не нужны PostgreSQL, Express, Vite, сборка или npm install.

## Открыть

Откройте `index.html` двойным щелчком. Передавайте клиенту **всю папку frontend-static**, включая assets, а не один index.html.

При установленном Node.js можно открыть терминал в этой папке и выполнить:

```powershell
npm start
```

Адрес: http://127.0.0.1:4173. Это только локальный просмотр. Он слушает 127.0.0.1, без API и базы. Другой порт в PowerShell:

```powershell
$env:STATIC_PORT = '4174'
npm start
```

Порты 5173, 3000 и 5432 относятся к исходному fullstack-проекту; эта папка от них не зависит. Отдельные `.html`-страницы — это адреса страниц, а не сетевые порты.

| Пример редактирования продуктов | admin.html |
| Проекты юридических текстов этой версии | privacy-policy.html, terms.html |
| Заголовок вкладки / описание для поиска | title и meta description в head каждого HTML |
| Логотип и favicon | assets/images/logo.png |
| Основные цвета, шрифт, радиусы | assets/css/theme.css |
| Общие элементы, кнопки, поля | assets/css/base.css |
| Хедер, навигация, меню пользователя | assets/css/navigation.css |
| Главная, каталог, FAQ | assets/css/storefront.css |
| Формы и кабинет | assets/css/account.css |
| Админка | assets/css/admin.css |
| Плавность и reduced motion | assets/css/motion.css; assets/js/ui.js |
| Дополнительные стили и бесплатный каталог | assets/css/custom.css |
| Подключение своей логики | assets/js/integrations.js |

Это обычные, несжатые CSS-файлы. Изменения видны после обновления страницы, компиляция SCSS не нужна. `main.css` задаёт порядок подключения. В `theme.css` меняются основные CSS-переменные; точечные декоративные оттенки находятся в стилях конкретного блока.

В HTML есть комментарии `EDIT: HERO`, `EDIT: LOGO`, `EDIT: PRODUCT CARD`, `EDIT: PHOTO`, `EDIT: DOWNLOAD`, `EDIT: HEADER`, `EDIT: FOOTER`, `EDIT: FORM`. Композиция с логотипом на главной оформляется классами `.hero-emblem` в assets/css/custom.css.

Header и footer находятся прямо в каждом HTML. При изменении общей ссылки обновите её на всех страницах. Это намеренно: в готовой передаваемой версии нет скрытого генератора, подгрузки шаблонов или HTML-разметки в JavaScript.

## Контент и бесплатная выдача

Сохранены стиль HYDRA, логотип, локальный Manrope, композиция, адаптивность, меню, FAQ, заглушки медиа и мягкие анимации. Название и краткое описание «Цифровой библиотеки» перенесены из доступного текущего каталога. Тексты про оплату и подписки адаптированы к бесплатной выдаче. Фактические файлы продукта и фото/видео клиент ещё не предоставил.

Добавить новый продукт:

1. Скопируйте product.html, например в product-tools.html.
2. Измените title, описание и содержимое.
3. Скопируйте `article.catalog-product` в catalog.html и при необходимости в index.html.
4. Измените название, описание и обе ссылки карточки на `./product-tools.html`.

Для фото замените соответствующий `div.media-placeholder` целиком:

```html
<img src="./assets/media/rage-preview.webp"
     alt="Описание того, что показано на скриншоте"
     width="1280" height="720" loading="lazy">
```

Если нужно добавить видео в «Примеры работы», замените соответствующий `div.media-placeholder` внутри `.showcase-card`:

```html
<video controls preload="none" playsinline poster="./assets/media/poster.webp">
  <source src="./assets/media/overview.mp4" type="video/mp4">
</video>
```

Для бесплатного скачивания добавьте настоящий файл в assets/downloads и замените кнопку `data-unavailable` в product.html:

```html
<a class="button" href="./assets/downloads/library.zip" download>
  Скачать бесплатно
</a>
```

Пока файла нет, кнопка честно показывает «Файлы скоро появятся». Не подставляйте ссылку на несуществующий архив.

## Что работает и что является шаблоном

Работают переходы между страницами, адаптивная навигация, выпадающее меню, FAQ, плавные переходы, якорная прокрутка и визуальная проверка полей. Учитывается системное отключение анимации.

Вход, регистрация, восстановление пароля, кабинет, профиль и admin — **публичные UI-шаблоны**, а не серверная авторизация. Формы не отправляют данные, не создают аккаунты, не сохраняют изменения и не показывают фиктивное «успешно сохранено». Поля без JavaScript выключены. Пароли после демонстрационного нажатия очищаются. Никаких cookies, аналитики или browser storage эти скрипты не создают.

Для подключения логики используйте `assets/js/integrations.js`. Скрипт интерфейса отправляет отменяемое DOM-событие `hydra:form-submit` с `detail.formId`. В обработчике вызовите `event.preventDefault()` до первого await и реализуйте запрос/состояния/переходы. Форму можно получить через `event.target`.

ID форм: login-form, register-form, reset-form, profile-form, product-form. Имя пользовательского поля — username, email, password, password-confirm; полей продукта — product-name, product-slug, description, download-path.

Проверка пароля, права администратора, хранение данных и защита запросов должны выполняться на backend. Скрытие ссылки или проверка роли в JS не защищает admin. В этой папке нет настоящих аккаунтов, ключей, базы или .env. Исходный рабочий backend, API и юридический модуль сохранены в client/server/shared основного репозитория; их можно использовать при дальнейшей интеграции.

Юридические страницы здесь — проекты именно для этой статической версии. Они не заменяют документы полного приложения. Заполните владельца, контакты, лицензию и фактический хостинг; при подключении форм, SDK и сторонних медиа обновите описание обработки данных.

## Публикация и передача

Для этой папки достаточно статического хостинга. Она не требует Web Service, Postgres или серверных переменных окружения. Загружается содержимое frontend-static вместе с assets; никаких секретов из основного проекта добавлять не нужно.

На сервисе с настройками сборки укажите папку публикации frontend-static (если Root Directory пустой) либо точку `.` (если Root Directory — frontend-static). Команда сборки не нужна; если поле обязательно, достаточно безвредной команды `echo Static site ready`. Для красивых URL без .html правила хостинга настраиваются отдельно; по умолчанию все ссылки уже работают с .html и в подпапке.

Публиковать нужно именно эту папку, а не client/dist исходного приложения. Если нужно передать один файл, заархивируйте frontend-static целиком. preview.mjs и package.json нужны только для необязательного локального просмотра, хостинг сам отдаёт HTML и assets.

После правок проверьте главную, каталог, продукт, формы и меню при ширине 390 и 1440 px; убедитесь, что ссылки и пути к своим файлам существуют. Не удаляйте assets/fonts/OFL.txt — это лицензия используемого шрифта.

## Проверка перед передачей

Проверены все 13 HTML-страниц при ширине 320, 390, 768 и 1440 px. Открытие через file:// и локальный HTTP работает, ссылки и локальные ресурсы существуют, шрифт загружается. Проверены меню мышью/клавиатурой, FAQ, диалог, формы без отправки данных и основной контент без JavaScript. Ошибок JavaScript, внешних сетевых запросов и горизонтального переполнения страниц не обнаружено.
