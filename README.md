# HYDRA

Сайт бесплатных цифровых материалов. Публичные страницы написаны на HTML, CSS и JavaScript. Регистрация, вход, список пользователей и админка работают через Node.js и PostgreSQL. Для проверки этих функций сайт нужно запускать вместе с базой данных.

## Быстрый запуск на компьютере

Нужны Node.js 20+ и запущенный Docker Desktop. Откройте PowerShell в папке проекта и выполните:

```powershell
npm ci
Copy-Item .env.example .env
docker compose up -d db
```

В `.env` заполните `OWNER_EMAIL`, `OWNER_USERNAME`, `OWNER_PASSWORD`. Это данные **первого и единственного главного администратора**. Имя пользователя: 3–32 латинские буквы, цифры или `_`; пароль: 12–128 символов. Затем выполните:

```powershell
npm run db:migrate
npm run admin:create
npm start
```

Откройте сайт: **http://127.0.0.1:4173/**. Админка: **http://127.0.0.1:4173/admin/**. Остановить сервер можно через Ctrl+C. После создания главного администратора сохраните пароль в менеджере паролей и удалите `OWNER_PASSWORD` из `.env`.

При следующих запусках достаточно `docker compose up -d db` и `npm start`. Команду `admin:create` выполняют **один раз для каждой новой базы**: повторный запуск не создаст второго главного администратора. Если порт 4173 занят, значит сервер, вероятно, уже запущен; откройте адрес сайта в браузере.

Ошибка `ECONNREFUSED` означает, что база по адресу `DATABASE_URL` недоступна. Проверьте Docker Desktop и выполните `docker compose up -d db`. Для собственной PostgreSQL создайте отдельную базу и замените `DATABASE_URL` в `.env`. Локальная база Docker хранит данные в томе `hydra_accounts`.

## Что уже работает

- Бесплатный каталог и страница продукта без оплаты.
- Регистрация, вход, личный кабинет, выход и смена пароля.
- Отдельный адрес `/admin/`: поиск пользователей, список аккаунтов и журнал действий.
- Три роли: обычный пользователь, администратор и главный администратор. Новая регистрация всегда получает роль пользователя. Только главный администратор назначает и снимает администраторов.

В журнал попадают регистрации, успешные входы и выходы, смена пароля и изменения прав. Пароли не отображаются в админке и хранятся в базе в виде хешей. Смена пароля завершает другие сеансы пользователя.

Подтверждение email и восстановление забытого пароля через почту пока не подключены. Админка управляет аккаунтами и правами; тексты и изображения меняются в файлах сайта.

## Где менять сайт

| Что нужно изменить | Файл |
| --- | --- |
| Главная страница | `public/index.html` |
| Каталог и описание материала | `public/catalog.html`, `public/product.html` |
| Вопросы и ответы | `public/faq.html` |
| Основные цвета и шрифт | `public/assets/css/theme.css` |
| Остальное оформление | `public/assets/css/` |
| Логотип | `public/assets/images/logo.png` |
| Страницы входа и регистрации | `public/login.html`, `public/register.html`, `public/account.html` |
| Админка | `public/admin/index.html` |
| Сервер аккаунтов и прав | `server/auth.js`, `server/admin.js` |
| Структура базы | `server/migrations/` |

Тексты каталога находятся прямо в HTML. Если меняете описание товара, проверьте и `public/index.html`, и `public/catalog.html`, и `public/product.html`: сейчас это отдельные статические страницы.

Примеры работы на главной и странице продукта пока представлены блоками для будущих скриншотов. Положите файлы в `public/assets/media/` и замените нужный блок `.media-placeholder` в `public/index.html` или `public/product.html`. Пример для фотографии внутри `<figure class="showcase-card">`:

```html
<img src="./assets/media/demo.webp" alt="Пример работы HYDRA" />
```

Файл для бесплатного скачивания положите в `public/assets/downloads/`. В `public/product.html` замените кнопку с атрибутом `data-unavailable` на ссылку, например:

```html
<a class="button" href="./assets/downloads/library.zip" download>Скачать бесплатно</a>
```

После добавления файла обновите текст «Файлы ещё не добавлены» на странице продукта. Страницы `public/privacy-policy.html` и `public/terms.html` содержат незаполненные сведения владельца и правила использования материалов: их нужно привести в соответствие с реальным сайтом до публикации.

## Показ сайта на GitHub Pages

GitHub Pages публикует только статические файлы. Команда `npm run build:pages` собирает визуальную версию в `pages-dist/`: главную, каталог, продукт, FAQ и информационные страницы. Из неё убраны вход, регистрация, личный кабинет, админка и обращения к API. Исходные страницы в `public/` и сервер в `server/` остаются для последующего размещения на хостинге с Node.js и PostgreSQL.

Файл `.github/workflows/pages.yml` публикует эту версию при отправке изменений в ветку `main`. В GitHub откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. После успешного выполнения workflow адрес проекта — `https://sp1ne8.github.io/hydra/`. Папка `pages-dist/` создаётся автоматически и не добавляется в Git.

Если заказчику нужны работающие аккаунты, GitHub Pages для этого недостаточно. Понадобится отдельный Node.js-хостинг и PostgreSQL либо перенос API на другую серверную платформу. Локальный запуск полной версии описан выше.

## Проверка и передача

`npm test` проверяет базовые правила паролей и конфигурации. Для проверки регистрации, сессий и прав в базе укажите `TEST_DATABASE_URL` тестовой PostgreSQL с правом создания схем и выполните `npm run test:integration`. Тест создаёт временную схему и удаляет её после завершения.

Передавайте исходники, `package.json`, `package-lock.json` и `.env.example`. Не передавайте `.env`, `node_modules`, локальную базу и секреты. Данные пользователей находятся в PostgreSQL; для переноса работающего сайта нужна отдельная резервная копия базы. Применённые SQL-миграции в `server/migrations/` не редактируйте: новые изменения структуры оформляйте новым файлом миграции.
